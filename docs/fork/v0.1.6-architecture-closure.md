## 3. DONE

### 3.1 §4 — the HTTP client pool was still unreachable from every pass

**Finding.** `retireIdleResources` and `retireSuspectResources` reached the HTTP client manager by
asserting `adapter.IdleConnectionKeeper`, which has **two** methods. The production owner has one:

```text
common/httpclient/manager.go   (*Manager) CloseIdleConnections()   yes
                               (*Manager) SetKeepIdleConnections   absent
```

So the assertion was false in every real build, and the fourth owner of reusable state — the pool
behind provider refresh, remote rule sets, the dashboard and the API — was still unreachable from
the reuse boundary, the memory trim and the DEEP_IDLE release. The regression test that was supposed
to prove otherwise stayed green because its double implemented **both** methods.

**Severity.** P0. This is the exact omission §4.1 names as the reason the walk was extended, and it
is the §9 failure mode verbatim: a test that hits the pool instead of the capability the walk
asserts.

**Evidence.**

```text
$ go test -tags "$TAGS" -run TestProbeProductionHTTPClientManagerCapability ./route/
    production *httpclient.Manager implements adapter.IdleConnectionKeeper: false
    production *httpclient.Manager implements {CloseIdleConnections()}: true
    WALK CANNOT REACH PRODUCTION HTTP CLIENT MANAGER
```

**Red test**, run after the capability was named but before the walk used it — so the failure is the
defect and not a missing symbol:

```text
--- FAIL: TestEveryOwnerClassIsWalkedExactlyOnce
    endpoint: an idle reusable connection survived the trim
--- FAIL: TestTheTrimAndTheBoundaryWalkTheSameOwnerSet
    the boundary did not discover every owner of reusable state
    expected: 4  actual: 3
```

**Minimal change.** `adapter.IdleConnectionRetirer` is the action half; `IdleConnectionKeeper`
embeds it, so all 26 existing implementors are unchanged. The walk asserts the action. Exactly one
owner becomes newly reachable and no owner's behaviour changes.

**Reverse-break.** Removing the `http` block from the new single enumeration turns three tests red
(`http: an idle reusable connection survived the trim`; `expected: 4 actual: 3`; `the boundary did
not reach a retire-capable owner that cannot drain: expected 1 actual: 0`).

### 3.2 §4 — the pushed DNS resolvers were unreachable

**Finding.** `protocol/openvpn`, `protocol/openconnect` and `protocol/tailscale` each register a
DNS transport through the manager's registry, and each builds the resolvers of the configuration
the far end pushed **privately** (`transport.NewUDPRaw` / `NewTLSRaw` / `NewHTTPSRaw`), holding them
in its own fields. Those inner transports implement the retire action; the owner did not forward it,
so the walk reached the wrapper and stopped. A pushed DoH resolver holds HTTP/2 connections that
were skipped by every pass — and these are precisely the endpoints a device is most likely to have
been asleep behind.

**Severity.** P1. Same class as 3.1, second location; this is why §4.2's single enumeration matters.

**Red test** (`protocol/tailscale`, runnable against the unmodified tree):

```text
--- FAIL: TestTheEndpointOwnedResolversAreRetireCapable
    Error: *tailscale.DNSTransport must implement adapter.IdleConnectionRetirer
```

**Minimal change.** A `CloseIdleConnections` that snapshots the resolvers under the existing
`access` RWMutex, releases the lock, and forwards to each — the same shape `protocol/vless` already
documents for its own transport.

**Reverse-break.** Emptying the forwarding body while leaving the method declared:
`a resolver held for a pushed route was not reached: expected 1, actual 0`.

`openvpn` and `openconnect` had **no test files at all**; each gains the same two assertions.
OpenConnect's routes live in a slice of route structs rather than a map, so its walk is the other
iteration and is asserted separately.

### 3.3 §4.2 — the owner enumeration is single-source

**Finding.** `retireIdleResources` and `retireSuspectResources` were two hand-written lists of the
same four managers, and `update()` a third. Adding an owner meant remembering all of them; the
failure mode of forgetting is silence, which rows 3.1 and 3.2 demonstrate twice.

**Minimal change.** `forEachRuntimeResource` is the one enumeration. Both walks are now only
"assert the capability, apply it, count". It does not deduplicate — see REFUTED.

### 3.4 §5 — a cancelled probe was read as a node failure

**Finding.** The health path treated every non-suspended dial error as a measurement that happened
and came back bad, and deleted the member's health evidence. Two conditions that are not facts about
the node fell into that branch:

* `net.ErrClosed` — **this process** ended the operation. A network transition closes the members'
  transports (`Outbound.InterfaceUpdated` → `transport.Close`), so every probe in flight across a
  transition fails with it. A transition therefore deleted the health history of members it caught
  mid-probe, and the group's selection could move because the device changed networks.
* `context.Canceled` — the caller withdrew.

This is §16 error 3 ("把 `net.ErrClosed` / generation cancellation 当节点故障") and §5.4's
"不污染 health", both violated.

**Severity.** P1, user-visible as a selection change on a network handover.

**Red test**, behaviour-level (a real URLTest round, asserting the history storage the selection
reads):

```text
--- FAIL: TestAProbeThatNeverHappenedLeavesTheHealthEvidenceAlone/this_process_closed_the_transport
--- FAIL: TestAProbeThatNeverHappenedLeavesTheHealthEvidenceAlone/wrapped_net.ErrClosed
--- FAIL: TestAProbeThatNeverHappenedLeavesTheHealthEvidenceAlone/caller_cancelled
    health evidence was deleted for a probe that never happened
```

**Minimal change.** `adapter.IsCallerCancellation` and `adapter.IsOwnTeardown`, composed by the
health path. The failover retry's inline cancellation test uses the same two predicates — behaviour
preserving, but "who ended this operation" now has one answer in the tree.

**Reverse-break.** `IsOwnTeardown` returning `false` fails five assertions across three tests at
both the fact layer and the behaviour layer.

**Not changed, on purpose:**

* `context.DeadlineExceeded` / `os.ErrDeadlineExceeded` stay retryable and stay health-relevant. A
  timeout is a measurement that happened; the round's own expiry is already caught by
  `b.ctx.Err() != nil` above.
* The two predicates are **two**, not one merged "not measured" predicate. See KNOWN LIMITATION.

### 3.5 §6 — two hand-written values that already exist in the repository

**(a) `scripts/ci/run-jiejie-suite.sh` pinned its own tag list.** The line carried the comment
"Keep in step with `release/DEFAULT_BUILD_TAGS`" and had drifted from it: the profile names sixteen

tags were never exercised, while `test/jiejie` documents that every test in the package must pass
under a release profile — the suite was verifying something other than what it claimed.

`tfogo_checklinkname0` is now **dropped** rather than appended: it records that
`-checklinkname=0` is passed, and `go test` cannot carry per-package `-ldflags` (cmd/go applies
`-ldflags` to a whole run or not at all). Naming it on a `go test` line is the exact "a tag claims a

`tag_checklinkname_test.go` enforces it there. The jiejie package does not import
`experimental/libbox`, so the tag was also inert.

**(b) The Go toolchain had six derived sources and one silent exception.** Six workflows use
`go-version-file: go.mod`; `windows-core-amd64.yml` wrote `GO_VERSION: "1.26.8"` by hand while
`go.mod` declares `go 1.25.5`. Nothing failed when that appeared and nothing would fail if it grew.

computes the legal `//go:linkname` pull set **from the runtime source of the toolchain it is compiled

toolchain the repository pins". A gate running under 1.26.8 answers a question about a runtime the

The divergence is **not flattened** — matching the upstream release toolchain is a legitimate goal
for one artifact and is the reason the workflow gives, and §1.2/§30 forbid exactly that kind of
cosmetic unification. What was wrong is that it was silent.
`cmd/internal/build_libbox/toolchain_source_test.go` now requires every workflow to derive its
toolchain or to declare the divergence **with its reason**, and computes the one thing no exemption
may authorise: a literal below the declared language version cannot build at all.

**Red-check:** emptying the declaration table fails with

```text

and the divergence is not declared
```

plus the stale-declaration guard.

**(c) Running the derived profile exposed a bug in the harness that reports the result.**
`KNOWN_FAILURES` is `()` — the file documents that as the intended state ("The list is kept, EMPTY,
rather than deleted"). On the bash this actually runs under (3.2 on macOS) an empty array expanded

aborts the script. So the classification step could never complete in exactly the state the file
declares to be correct, and the `UNEXPECTED FAILURE` report and its `exit 1` gate were

under `bash 3.2.57` with `set -euo pipefail`: empty → no iterations, the gate is reached; populated
→ every element iterates, including one containing a space. Reproduced and re-verified end to end
with a planted `--- FAIL:` line, which now prints `UNEXPECTED FAILURE: SomeTest` and reaches the
gate with `unexpected=1`.

### 3.6 §7 — the two lifecycle orderings are now pinned as orderings

§7.2 forbids reversing either ordering. The existing lifecycle tests pin **effects**, and effects are
not order: a bridge that paused the level first and measured afterwards produces identical effects in
a single-threaded test, because both calls still happen. What it changes is the **window** between
them, and only a concurrent fact arriving inside it can see it.

Two tests observe the order itself:

* **wake** — a sequence recorder shared by the pause callback (where the level is recorded and from
  which the production bridge applies the pause event) and a reuse observer. Expected
  `[level-paused, reuse-verdict, level-released]`.
* **sleep** — a `deviceAxis` wrapper that, at the moment the level is paused, advances the clock
  past the retire band and asks whether a resume would produce a boundary right there. If the edge
  had not been recorded first there would be no sleep on record and `Resumed` would publish nothing.

**Reverse-break**, both orderings at once:

```text
expected: [level-paused reuse-verdict level-released]
actual:   [level-paused level-released reuse-verdict]
"the level was paused BEFORE the sleep edge was recorded"
```

No production code changed for §7. §7.4 forbids structural refactors and none was needed.

## 6. UNCHANGED BY DESIGN

* **`update()` does not use `forEachRuntimeResource`.** It is a *policy* walk: it needs each owner's
  kind for a log label, its own referenced/device-paused inputs, it diverts on-demand endpoints into
  a list of their own, and it applies the eligibility axis rather than the retire action. Folding it
  in would mean dispatching on `kind` — a cosmetic unification that trades a real omission risk for a
  string switch. Adding an owner there is a policy decision ("does this owner have an eligibility
  axis at all?") and belongs in that function. §1.2.
* **`ServiceManager.Services()` is not walked.** No service implements a pool capability today
  (verified: no `CloseIdleConnections` under `service/` or `experimental/clashapi/`), and every
  service-owned HTTP pool goes through `httpClientManager.ResolveTransport`, which is already owner
  row 4. Adding an owner class with zero implementors would be a type assertion per service at every
  trim for no coverage. With the single enumeration, adding it when a real service-owned pool appears
  is a one-line change in one place.
* **Network epoch / reuse epoch / device EDGE / device LEVEL remain separate.** No second lifecycle,
  network or recovery authority was created. `common/runtimecoord` is untouched.
* **No mega `RuntimeResource` interface.** Four capability interfaces stay independent:
  `IdleConnectionRetirer`, `IdleConnectionKeeper`, `ReuseSuspect`, `OnDemandEndpoint`, plus
  `Rebindable`. The round *split* one interface rather than merging any.
* **Retry / health / penalty policy remain separate.** `RetryThisFlow` and `PenalizeMemberGlobally`
  are still two functions with two answer sets. No `FailureClass` enum was introduced.
* **`common/httpclient.Manager`'s `ResetNetwork` was not made idle-only and was not touched.** It
  swaps inner transports, which is right for a network change and wrong for a resume; the walk uses
  its `CloseIdleConnections`.
* **Apple/Android platform adapters, protocol state machines and transport pools untouched.**
  `clients/*` never entered; submodules uninitialised.

## 7. KNOWN LIMITATION

**Caller cancellation and network-generation cancellation are still one error value at the
classifier.**

`route/dialSetup.go` cancels an in-flight dial when the network generation moves, and its
closed-branch comment states the consequence: the dial "reports the same `context.Canceled` a caller
cancellation does, which the load balance classifiers already treat as neutral rather than as a path
failure".

Consequences, stated rather than papered over:

* The failover retry cannot satisfy both §22 ("no retry after caller cancellation") and §5.4 ("the
  new generation's demand continues") at the same time, because it cannot tell the two apart. It
  currently chooses the first: a flow whose dial was cancelled by a transition fails and the
  application re-demands. No penalty is recorded and no health history is deleted, so §16 error 3 is
  **not** violated — the requirement in force is met.
* Closing it properly is not a classifier change. A retry after a generation cancellation must run
  under a **new** generation's setup context, and `DialWithFailover` receives the *cancelled* setup
  context: retrying under it would burn the flow's only alternate on a dial that is cancelled on
  arrival and could earn a second penalty decision. Re-deriving the setup belongs to the layer that
  owns the gate, so the fix is a cross-layer ownership change, not a predicate.
* This round did the part that is safely closable: `adapter.IsCallerCancellation` and
  `adapter.IsOwnTeardown` now exist as **two separate facts** rather than one inline pair of
  `errors.Is` tests, so the distinction can be expressed later without renaming anything.
  `TestFailureFactsAreClassifiedByBehaviour` pins that the three facts are disjoint.

**`sing-mux` still has no no-new-stream/draining API**, so the multiplex dialer behind a VLESS
outbound cannot participate in `ReuseSuspect`; the outbound's `RetireSuspect` deliberately does not
forward to it, and its idle release is `streams == 0` only. Unchanged from the recorded limitation in
`post-wake-reuse.md`.

**One pre-existing test failure is reported, not fixed:** `TestJiejieNaiveSharedTLSLifecycleIsSingleOwner`
(Naive inbound TCP listener closed twice, so `Box.Close()` returns `net.ErrClosed`). It is outside
this round's three directions, it is proven pre-existing (§3.5(c)), and it is deliberately left in
the failure list rather than added to `KNOWN_FAILURES` so it stays visible. Routed to the integrator.

**Not reproducible locally:** Apple / Android / Windows / Xray-interop workflows, real-device
behaviour, and libbox artifact builds. Per §23 these are recorded as not reproduced, not claimed.

## 8. REFUTED

Suspected, audited, **not** a defect. This section is the point of the round as much as §3.

1. **"The walk double-acts on an object owned by two managers."** (§11.3) Not reachable. The four
   owner classes are disjoint by type — a value is an outbound, an endpoint, a DNS transport or the
   HTTP client service, never two — and each manager lists a given object once. No group outbound
   forwards a retire action to its members (verified: `protocol/group` has no pool capability), so a
   member reached through its group as well as directly is not possible. A dedup set would guard a
   case that cannot occur and would hide the day those facts stop holding. Asserted structurally by
   `TestEveryOwnerClassIsWalkedExactlyOnce`/`TestTheTrimAndTheBoundaryWalkTheSameOwnerSet` (exact
   per-owner counts, not floors).
2. **"`dns/transport.HTTPSTransportWrapper` has `CloseIdleConnections` and no
   `SetKeepIdleConnections`, so it is a second over-assertion gap."** It is not an
   `adapter.DNSTransport`: it is the private inner transport of `dns/transport.HTTPSTransport`
   (`https.go:56`), and the manager lists the owner, which implements both methods.
3. **"Every endpoint is unreachable, which is a gap."** Endpoints implement
   `SetKeepIdleConnections` (suspend) and no retire action, so the retire arm is inert for them **by
   contract** — a suspended tunnel is a much larger action than a trim and must not be a reconnect
   trigger. The arm is kept and asserted anyway, so a future endpoint that grows a pool is covered.
4. **"`EADDRNOTAVAIL` / `ENETDOWN` are classified inconsistently, so the classifiers have drifted."**
   Three readings, all correct for their own question: retryable to the failover retry, explicitly
   *not* evidence about a member to the ledger ("the local interface, which every member shares"),
   and an address-family verdict to the dual-stack scheduler. This is §5.2's own example and is why
   no universal class exists. Pinned as a table row so the disagreement is deliberate and visible.
5. **"`build-macos-client.sh` maintains a second copy of the tag set."** It maintains a *required
   feature* list — presence versus requirement, a different fact, in one place — and it guards the
   profile file rather than restating it. `build-server.sh` reads
   `release/DEFAULT_BUILD_TAGS_OTHERS` instead of restating it. Neither is a duplicate.
6. **"A timer was reintroduced to replace a platform fact."** The governor owns exactly two timers
   (`wakeTimer` for the staggered release after a wake, `idleTimer` for the DEEP_IDLE deadline). Both
   implement policy windows. The device level is released by the unlock fact and by nothing else, and
   `box_lifecycle.go` states why a duration cannot answer "is somebody using this device".
7. **"The lifecycle orderings are wrong."** Both are correct as written; what was missing was a test
   at the ordering level, which §3.6 now provides.
