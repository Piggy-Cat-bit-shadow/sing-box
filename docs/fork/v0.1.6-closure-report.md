# v0.1.6 closure — acceptance report

**Base `17b176a18` → FINAL `c7a1ef193`** (`local == origin/testing`), ordinary pushes only, no tag,
no Release. 22 commits this round. Four agents worked in **isolated worktrees** and committed on
their own branches; the integrator cherry-picked with `-x` and never staged a shared tree.

## The finding that matters most

**Two independent agents found that a previous round's "fixed" was never real** — the same defect,
reached from different directions.

The runtime resource walk asserted `adapter.IdleConnectionKeeper`, which has **two** methods. The
production owner has **one**:

```
common/httpclient/manager.go   (*Manager) CloseIdleConnections()   yes
                               (*Manager) SetKeepIdleConnections    ABSENT
```

So the assertion was **false in every real build**. The fourth pool — provider refresh, remote rule
sets, dashboard, API — stayed unreachable from the reuse boundary, the trim and the DEEP_IDLE
release: exactly the omission the walk had been extended to close, believed closed, with a green
regression test. The test stayed green because **its double implemented both methods**, so it tested
the pool rather than the capability the walk asserts. Proven with `production *httpclient.Manager
implements adapter.IdleConnectionKeeper: false`; fixed by naming the action half, with a red-check
(`expected: 1 actual: 0`). A second instance fell out of the same audit: openvpn, openconnect and
tailscale build their pushed DNS resolvers privately, so the walk reached the wrapper and stopped,
skipping a pushed DoH resolver's HTTP/2 pool on every pass.

## Per work package

**Sniff closure.** `PeekStream` decided its retry by rebuilding a filtered, flattened, de-duplicated
multi-error every round — an eight-read ClientHello built seven of them and discarded all seven. Now
the round's failures are OR-ed and the aggregate is built once. Deterministic results (allocations,
exact across all ten samples): `PeekStreamDNS` 17→12 allocs / 5266→**600** B/op; fragmented ClientHello
401→212 / 110Ki→70Ki; `PeekPacketQUIC` 85→77 / 10664→**7356**. The HTTP gate costs exactly **+1
allocation** on paths that reach the parser and removes 4.4–5.1 KB from every path that does not.
Two of the five QUIC candidates were **abandoned with proof**: `-gcflags=-m` shows the mask and nonce
arrays escape into `cipher.Block`/`cipher.AEAD` interface methods, so the "stack" arrays would
allocate exactly what `make()` does while reading as if they did not — the prompt's own precondition
is unsatisfiable. That investigation also caught a real trap: this AEAD's `NonceSize()` is **8, not
QUIC's 12**.

**Apple lifecycle.** The device axis was a latch with no publisher. The asymmetry is the fix: **a
display turning on is not an unlock** (a push lights the lock screen), while `lockstate == 0` is the
one fact that releases the level; no timer, because no timer can tell a locked phone from an unlocked
one. A **second implementer gap** was found — `BridgeServiceSession` under `#if os(macOS) || JAILBREAK`
returns `String` where Go declares `*StringBox`, and the iOS configuration never compiles that file,
which is exactly why the release gate stayed green. Both client patches are now on a remote
(`2b23330d4`, branch + tag `libbox-stringbox-abi-2`); the observer patch had been on **no** remote.

**Architecture closure.** A real defect was closed in the health path: it deleted a member's evidence
for anything that was not `ErrResourceSuspended`, so `net.ErrClosed` (a network transition closing
members' transports mid-probe) and `context.Canceled` were recorded as **node failures** — visible to
the user as a selection change during a handover. Fixed with two disjoint fact predicates, **no
universal `FailureClass`**. Coverage is now a single enumeration instead of three hand-written lists
of the same four managers. A tag line whose own comment said "keep in step" had drifted 16→4 tags,
and a workflow hard-coded Go `1.26.8` where `go.mod` declares `1.25.5` — the toolchain being the
*input* to the linkname guard's computed set. Neither flattened; both gated.

**Residual sweep + uTLS.** Verdict is **GO on technical merit**, and it is the one item that cannot be
landed from here: `fingerprint: firefox` and `safari` produce greetings with **no X25519MLKEM768**
share, and current Xray rejects them (`authentication failed or validation criteria not met`), while
the same scenarios pass against v26.3.27 — so the reference's requirement changed, not this code. A
version bump does **not** fix it (v1.8.8 still ships Firefox 120 / Safari 16.0; the one branch that has
them is a 175-commit rebase, refused as a freeze change). **Scope is wider than the brief**: `edge`,
`ios` and `qq` fail identically and no upstream preset fixes them, so the prepared fork repairs
firefox+safari only; `random` draws a hybrid-less preset four times in five. The minimal patch is
committed with a red-checked tripwire register. One flaky XHTTP gate was also made deterministic
(reproduced at `-count=200`; assertion unchanged, precondition fixed).

## Deliberately not done

Adaptive `Skip` (the dependency analysis still stands and no new evidence appeared); the two
pre-existing detection changes (HTTP header fragmentation, SSH truncated banner) because fixing either
changes detection for inputs currently classified correctly — the prompt asked for a cheap gate, not a
detection change; `§7.4`'s forbidden structural refactors; no universal `FailureClass`; no mega
interface (the round **split** one instead).

## Infrastructure incident, recorded

All four `/tmp/v16-*` worktrees were **deleted from disk mid-run**. No committed work was lost — every
branch ref survived in the shared object store, which is the entire reason the isolation model worked
— and the integrator recovered all of it from the branches. Uncommitted work in the wiped trees was
lost; one agent re-applied its own. Worth pinning worktrees somewhere durable next time.

## Known limitation, stated not hidden

Caller cancellation and network-generation cancellation are still **one error value** at the
classifier, so the failover retry cannot satisfy both "no retry after caller cancellation" and "the
new generation's demand continues". It currently picks the first, and no penalty, health or reboot
rule is violated. Closing it is not a classifier change: a retry after a generation cancellation must
run under a **new** generation's setup context, and `DialWithFailover` receives the cancelled one —
retrying under it would burn the flow's only alternate on a dial cancelled on arrival. The two facts
now exist separately and their disjointness is pinned.

One pre-existing failure is **reported, not hidden**: `TestJiejieNaiveSharedTLSLifecycleIsSingleOwner`
(Naive listener double-close), proven pre-existing three ways, deliberately **not** added to
`KNOWN_FAILURES` — that file's own contract says a populated list is how a real regression hides
behind a label. Deriving the profile also exposed that the harness's reporting gate was **unreachable**
(`KNOWN_FAILURES=()` + bash 3.2 + `set -u` aborted before it); fixed.

## Can it be released?

**Closer than last round, and still not on my word.** The kernel builds tagged and untagged, the whole
suite is green, and the "inherent" failure from earlier rounds is gone. Two things gate a release
verdict, and both are decisions rather than defects: **the uTLS fork is not landed**, so `firefox`,
`safari`, `edge`, `ios`, `qq` and most `random` draws are broken against the current reference while
`chrome` works; and **the two client revisions must be pinned** to the commits that carry their
StringBox call sites, since neither pinned revision compiles against a rebuilt framework. Land those,
then run one acceptance pass against a single frozen SHA — the existing Actions evidence still spans
several, and stitching it into one verdict is what the work order forbids.
